# Echo ADK engineering doorway

Read the applicable global and ancestor instructions before engineering. On QUENCH,
the global doorway is `C:\Users\Sovereign\.codex\AGENTS.md` and the execution
constitution is `C:\Users\Sovereign\.codex\policies\execution-constitution.md`.
Also read this repository's `CONTRIBUTING.md` and `SECURITY.md`.

Work on an isolated `agent/*` branch and preserve unrelated changes. Run the
installed Echo preflight with the actual repository, task directory, commit,
session, and role. A build-stage pass is not release authorization. Production
activation retains the existing exact-commit certification, target identity,
authenticated capability registration, verification, and recovery requirements.

Preserve security rules R1–R5 in `SECURITY.md` and the versioned HTTP contracts in
`docs/CONTRACT.md` and `docs/CONTRACT_V2.md`. Keep optional host dependencies behind
extras. Never include credentials in source, logs, test evidence, or model context.

Use `deploy/README.md` and `echo_adk/sdk/README.md` for deployment preparation.
An SDK manifest is a proposal until the real registrar admits it and authenticated
readback verifies the installed capabilities. Back up the complete state before
an upgrade; do not run an older binary against an upgraded database without the
reviewed reconciliation described in `docs/CONTRACT_V2.md`.

Validate applicable changes with the repository's lint, format, and test commands
and the supported Python versions described in `CONTRIBUTING.md`. Report local
tests, live service verification, certification, registration, and deployment as
separate observed outcomes.
